## The Highest Domino

**Three executives, three nominations:**

- 👔 **CEO: Business Model** — wrong tier structure is shaping every user acquisition and retention outcome right now. A broken model scales its own damage.
- 💻 **CTO: Value Proposition (agent performance)** — if resolution rate is low, merchants aren’t experiencing the core promise. Can’t build the next layer on a cracked foundation.
- 📣 **CMO: Growth Strategy (activation)** — if merchants aren’t activating past signup, no other dimension can be tested. Invisible churn is the most dangerous failure mode for a live early-stage product.

**Facilitator Ruling: The three risks form a chain, not independent dominoes.**

> **Activation (Growth) → Agent Performance (Value Prop) → Tier Conversion (Business Model)**
> 

A merchant who doesn’t activate never experiences agent performance. A merchant who experiences poor agent performance never converts tiers. A merchant who hits the cap before seeing value churns instead of upgrades.

**The Highest Domino is Value Proposition performance — specifically:**

> *“Are merchants who deploy Bonsai agents experiencing resolution quality good enough to trust the agent with real customer conversations — and is this happening fast enough that merchants don’t abandon the product before reaching that moment?”*
> 

**Why this is the domino:**

- If agent performance is below threshold → merchants don’t deploy fully → activation fails → business model never tested
- If agent performance is strong → activation improves → tier conversion becomes testable → roadmap decisions become data-driven
- **Adjacent domino to test simultaneously:** Whether the self-serve tier is sorting for the right customer or creating a cohort that will never convert

## Selected Targeted Validation Technique

### ✅ Product Tests + User Interviews — Two-Week Behavioral Audit

**Rationale:** The product is live. Behavioral data exists right now. This is no longer a hypothesis to test theoretically — it’s an experiment already running that we haven’t read yet. Product Tests are the highest applicability technique for a live product. Paired with five targeted interviews to explain the *why* behind the *what*.

---

### Track 1 — Product Analytics (Week 1)

Pull and analyze the following metrics against the DAM framework:

| Metric | What it tells us | Target signal |
| --- | --- | --- |
| **Activation rate** | % of signups who deploy a live agent within 14 days | > 40% = healthy |
| **Agent resolution rate** | % of conversations resolved by AI without escalation | > 60% = VP delivering |
| **Channel breadth at Day 30** | Average channels connected per active merchant | > 3 = DAM path |
| **DAM achievement rate** | % of merchants who have hit all three DAM thresholds | Baseline TBD |
| **Tier distribution** | Split between self-serve vs. managed tier | Watch for developer skew |
| **Tier conversion rate** | Self-serve → managed upgrade rate and trigger | Identify upgrade moment |
| **Cap hit rate** | % of managed merchants hitting 3k cap | High = cap too low or wrong cohort |
| **Silent churners** | Signed up, connected API key, never deployed publicly | Identify and interview |

---

### Track 2 — Five User Interviews (Week 1–2)

| Interview | Profile | Key question |
| --- | --- | --- |
| 1–2 | Active managed tier merchants | *“Walk me through your first week. When did it click?”* |
| 3–4 | Self-serve merchants who never deployed publicly | *“What stopped you from going live?”* |
| 5 | Merchant who went quiet after signup | *“What did you expect that you didn’t find?”* |

---

### Decision Rules: What We Build Next

| Condition | Decision |
| --- | --- |
| Resolution rate > 60% AND activation > 40% | Agent layer is performing. Proceed to build financial view. |
| Resolution rate < 40% OR activation < 25% | Optimize onboarding and agent quality before building anything new. |
| Self-serve cohort = mostly developers, not operators | Restructure tier entry point. Make managed tier the default path. |
| Cap hit before Day 30 with high churn | Remodel the 3k cap (raise cap, or gate it only after value is confirmed). |
| Interviews reveal expectation gap (VP > product) | Rewrite landing page to reflect current product, not full vision. |

## Session Notes — Key Tensions Surfaced

1. **The activation chain.** Activation → Agent Performance → Tier Conversion is a sequential dependency. Fixing the middle (agent quality) fixes downstream (tier conversion) and upstream (activation word-of-mouth). This is why VP performance is the highest domino.
2. **The self-serve tier sorting problem.** Requiring an API key as the entry point may be filtering for technically curious developers rather than operationally motivated merchants. This is a structural pricing architecture question, not a marketing question.
3. **Expectation gap between vision and current product.** The full PMF narrative VP promises five sub-benefits. The live product delivers one. The landing page and marketing may be selling the vision while the product delivers the first chapter. This gap should be closed proactively — either by updating the landing page to reflect the current product, or by accelerating roadmap to close the gap.
4. **No new features before the audit.** All three personas agreed: zero new engineering investment until the two-week behavioral audit is complete. The data already exists. Read it first.
